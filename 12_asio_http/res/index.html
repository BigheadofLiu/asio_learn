一次请求如何流动

每一层只处理自己的职责，让网络连接、协议解析与文件响应保持清晰边界。

01 / ACCEPT

建立连接

acceptor 异步等待客户端，连接建立后把 socket 交给 connection_manager。

02 / READ

读取字节

connection 持续读取 TCP 数据，并保持对象与缓冲区在异步期间有效。

03 / PARSE

解析请求

request_parser 逐字节识别请求行、Header 与 HTTP 报文结束位置。

04 / REPLY

返回资源

request_handler 校验路径并读取静态文件，reply 生成状态行与响应头。

核心模块

从这些模块开始阅读，可以快速建立 HTTP 服务端的整体心智模型。

Connection

管理单条 TCP 连接的异步读写、请求缓冲区和响应生命周期。

Request Parser

使用状态机解析 HTTP 请求，展示流式协议不能假设一次读取完整到达。

Request Handler

完成 URL 解码、路径安全检查、MIME 判断与静态文件响应。

void server::do_accept() {
    acceptor_.async_accept(socket_,
        [this](boost::system::error_code ec) {
            if (!ec) {
                connection_manager_.start(
                    std::make_shared<connection>(
                        std::move(socket_),
                        connection_manager_,
                        request_handler_));
            }
            do_accept();
        });
}
